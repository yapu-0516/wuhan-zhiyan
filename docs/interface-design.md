# CityEye 界面设计说明

## 方向

界面沿用 `data-terminal`（seed `114499475`）：城市地图是主画面，面板和工具栏退到辅助层级；
选择状态统一使用 1px 青色线，状态色只出现在数据、风险等级和必要操作上。

产品特征是“武汉汉口沿江城市运行指挥台”：

- 中性黑作为主背景，避免深蓝模板感。
- 江水青只用于当前选择、实时连接和关键数据。
- 数字使用正文无衬线体的等宽数字变体，ID 与格式字段使用单一一套等宽字。
- 地图、事件流、监测源和 AI 分析都使用同一套平面面板与 4–6px 紧凑圆角。

## 各页面问题

| 页面 | 首先回答的问题 | 主视觉 |
|---|---|---|
| 城市总览 | 当前城市哪里最需要关注 | 三维地图，左右两侧为辅助指标与事件流 |
| 事件中心 | 哪些事件需要核查或处置 | 状态计数条与可排序事件表 |
| 城市监测 | 哪些感知源和城市设施异常 | 区域概况、数据源卡、交通与建筑监测 |
| AI 分析 | 当前数据能否被算法检出 | 输入样本、实际算法信息与运行结果 |
| 数据管理 | 数据资产在哪里、是否已入库 | 类型分布、入库状态与资产表 |

## 本轮调整

- 全局底色从偏蓝黑收敛为中性黑，补齐两档灰度和面板边界层级。
- 核心面板标题、指标标签、事件摘要等主要数据字号上调到 13–14px。
- 侧栏选中态改为中性底加一条青色线，不再同时强调底色、图标和线条。
- 地图工具条按地图控制与业务动作分组，移除不必要的彩色按钮底。
- 手机底部导航由 8 个截断入口改为 4 个主入口和“更多”面板。
- 事件 KPI 去除渐变、发光和 emoji，保留状态色细线与数字。
- 事件详情、情景推演和 AI 分析页统一为中性平面面板。
- 监测页数据源改用 `UAV/SAT/CAM/H2O/STR/TRF` 等技术缩写，不再使用 emoji。

## 真实城市视图中的事件层级

城市总览只保留一套真实感城市视图。实时路况、事件和 AI 图层叠加在同一画面，
不再切换“天际线 / 态势”两套视觉模式。事件显示优先级综合三项信息，不改变事件中心的业务排序：

城市主体采用统一的“城市数据块”语言：冷灰卫星底稿、实体建筑、方向光照和清楚的屋顶层次。
高度只改变真实体量，不改变发光亮度；底图降饱和后只提供道路、江岸和街区轮廓，不与数据块争夺注意力。
道路默认使用低对比灰绿色，只有轻度以上拥堵才转为暖色，避免整套路网形成“数据网格”。

默认底图使用降饱和卫星影像，与建筑数据块、道路和 HUD 形成同一套视觉语言；纯暗色底图保留为手动选项。
默认使用 822 栋 OSM 真实轮廓生成完整城市体量，普通建筑保持中性灰，只有沉降风险转为琥珀/砖红。
“全城楼”仍作为数据核查用的可选增强层，不自动加载 8,000 多栋派生体块。

- 严重程度：低 12、中 40、高 70、重大 100；
- 处置状态：待核查 +42、监测中 +20、处置中 +14、已办结 -40；
- 时间新鲜度：15 分钟内 +30、1 小时内 +20、6 小时内 +10、24 小时内 +4。

地图只给当前选中项、优先级前三项和最多六个高等级事件保留彩色图标、标签、涟漪或光柱；
其余事件仍保留可点击的小尺寸静态点位，但取消发光并降低透明度。这样既不隐藏数据，
也不会让所有活动事件同时争夺注意力。

地图同时按行政区聚合未办结事件：片区圆的面积对应当前待办密度，冷灰表示一般片区，
琥珀和砖红表示片区内存在高等级事件；地图标签只显示“片区 · 待办数”，避免与右侧明细重复。
右侧事件流默认进入“优先”视图，与地图高亮使用同一优先级函数。

点击事件后，事件点、关联建筑和关联路段使用同一条选择关系高亮。建筑保留青色选中轮廓，
路段使用当前路况色但提高不透明度，便于从列表快速回到真实空间对象。

应用外壳默认收为 60px 图标导航栏，为城市画面释放横向空间；悬停或点击底部展开按钮后
恢复完整导航，并记住用户选择。

片区圆只作为局部定位范围，不覆盖整块城市底图；圆面积表示待办量，标签保持可读字号。
宽度低于 1100px 时自动收起左右 HUD，只保留边缘把手，避免平板宽度下两块 248px 面板
挤压地图；全屏启动层在应用挂载后的首帧立即撤除，后续加载信息由地图自身的状态提示承担。

## 应急演练页

演练页沿用 `data-terminal` 的方向：地图是主画面，事件控制条、推演过程和结果面板只承担
指挥辅助。顶部在活动态直接显示事件类型和事件名，倍速选择使用 1px 青色下划线，不再使用
填充式 segmented control。

- 右侧事件卡优先显示受影响人员、车辆、关联建筑和疏散进度；火焰、烟雾等细分指标后置。
- 推演时间线固定在操作区，宽度不足时只保留最新一条过程事件。
- 当前风险半径、动态重规划次数、出口数和封闭路段数使用 2×2 状态组。
- 桌面活动态将图例移到事件卡左侧，避免遮挡图例；宽度低于 900px 时隐藏图例。
- 手机活动态使用固定的四项影响摘要和疏散进度条，无需滚动即可看到关键数值。
- 事件说明在手机端限制为两行，完整文本仍保留在 DOM 中。
- 交通拥堵使用独立车辆摘要：平均车速、排队车辆、受影响车辆和累计绕行；
  手机端不再复用人员疏散摘要。

## 验证

- `dashboard`、`event-center`、`monitoring`、`data-management`、`ai-analysis/fire`
  在 1440、768、390 三种宽度下均由 tasteskill inspector 检查。
- 页面检查为 0 FAIL；业务构建、ESLint、类型检查与自动化测试另行执行。
- 应急演练页在 1440、768、390 三种宽度下复检为 0 FAIL / 0 WARN。
- 活动态与交通疏导页通过 WCAG 2 A/AA 自动检查，违规数为 0；前端 49 项测试通过。
- 生产构建、ESLint、TypeScript 类型检查通过。
- 监测页仍保留 11–12px 的图表刻度和辅助元信息；正文和主要数据标签为 13–14px。
- 事件优先级规则由 `eventPriority.spec.ts` 覆盖，包括新鲜待核查事件、重大事件、
  高亮数量上限和选中事件保底展示。

## 设计边界

- 空间推演的水面、影响范围和人员移动仍是明确标记的模拟结果。
- 本轮不改变算法、事件状态机、数据来源或空间计算逻辑。
- 真实生产数据接入后，只需替换数据和状态来源，不改变当前视觉层级。
