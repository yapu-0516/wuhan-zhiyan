# 城市之眼 · 算法说明

算法包 `algorithm/cityeye_algo` 实现火灾、交通、建筑、内涝四类事件的**经典**图像与时序分析方法，只依赖 numpy 与 Pillow
（连通域标记、形态学、Otsu、积分图滤波等算子均为纯 numpy 实现）。每个分析器输出统一结构：

- `detected` / `confidence`（0~1，未检出时为 0）/ `summary`（中文结论）/ `level`（语义等级）；
- `detections`：像素检测框 `[x, y, w, h]`；`metrics`：指标字典；`series`：时序类分析的绘图数据（观测 + 预测）；
- `artifacts`：标注图（JPEG）或时序图（PNG），作为事件证据图。

**诚实原则**：系统中所有"检出"都来自算法在输入数据上的实际计算；算法未检出时不生成事件。示例影像与传感器序列是
合成演示数据（见 `data/scripts/generate_samples.py`），在示例描述、数据资产与事件描述中均有标注。

## 1. 火灾 · FlameNet-Lite（`fire.py`）

| 步骤 | 内容 |
| --- | --- |
| 色彩规则 | **YCbCr**（Celik & Demirel, 2009）：`Y>Cb`、`Cr>Cb`、`Y>Ȳ`、`Cb<C̄b`、`Cr>C̄r`、`|Cb−Cr|≥τ(40)`；**RGB/HSV**（Chen et al., 2004）：`R>R_T(135)`、`R≥G>B`、`S≥(255−R)·S_T/R_T`（S_T=60）。两组规则取交集 |
| 焰心补全 | 黄白色焰心饱和度低、`Cb≈Cr`，会被色彩规则漏掉；`Y>205 ∧ R>235 ∧ G>165` 且与候选相邻的像素并入 |
| 形态学 + 连通域 | 3×3 开运算去噪、7×7 闭运算补洞，8 邻域连通域，面积 < 0.04% 画面的剔除 |
| 区域级校验 | 置信度 = 0.34·焰心占比 + 0.26·亮度纹理（区域内 Y 标准差）+ 0.12·规则一致率 + 0.12·平均红色强度 + 0.08·形状不规则度 + 0.08·面积；要求置信度 ≥ 0.55 且焰心占比 ≥ 3% |
| 烟雾 | 与火焰相连、低饱和（S<0.2）、比全图中位亮度更亮、低纹理（局部标准差 <7）的灰雾连通域占火点邻域（半径 16% 画面）的比例，扣除全图背景同类像素占比 |

区域级校验是抑制误报的关键：红瓦屋面、橙色彩钢瓦、落日色车辆都能通过色彩规则，但没有黄白焰心、亮度均匀。
在示例 `fire-05`（黄昏 + 大量红瓦屋面 + 橙色车辆）上 10 个暖色候选区域全部被否决；正例焰心占比 21%~38%、
亮度标准差 32~48，反例焰心 ≤ 0.6%、亮度标准差 3~7，区分度很大。

**局限**：纯色彩方法对大面积霞光、强烈的橙色灯光仍可能误报；未利用时序闪烁特征（单帧分析）；烟雾得分在浅色屋面上的火点处会偏高。

## 2. 交通

### 2.1 TrafficPulse · 时序路况（`traffic.py`）

- **TPI 映射**：相对速度 `r = v / v_ff`（`v_ff` 自由流速度：有限速时取限速，否则取序列 90 分位速度），分段线性映射到 0~10：
  `r≥0.80 → 0~2 畅通`、`0.65~0.80 → 2~4 基本畅通`、`0.50~0.65 → 4~6 轻度`、`0.35~0.50 → 6~8 中度`、`<0.35 → 8~10 严重`。
  五级划分沿用北京 DB11/T 785《城市道路交通运行评价指标体系》的 TPI 分级；标准原文以拥堵里程比例计算路网指数，
  这里对单条道路用相对速度近似，属于工程简化。路网 TPI = 各道路 TPI 按长度加权平均。
- **持续拥堵**：15 分钟滑动平均后的 TPI ≥ 6 且持续 ≥ 15 分钟（实时监测场景为 1 分钟）记为一个拥堵时段，给出峰值时刻与早晚高峰。
- **短临预测**：阻尼趋势 Holt 双指数平滑（Gardner & McKenzie, 1985；α=0.5, β=0.2, φ=0.9）预测未来 30~60 分钟车速并换算 TPI；阻尼避免线性外推过冲。

### 2.2 RoadOcc · 航拍路面车辆占有率

1. 沥青掩膜（S<0.2，0.1<V<0.5）闭运算填补车辆 / 标线空洞，再扣除"外部"非沥青区域（触及画面边缘或面积 >1.5% 的连通域，
   如人行道、地面、行道树带），防止路面外溢；悬挑到路面上方的树冠与人行道连通，因此也被排除。
2. 局部背景差分（41×41 窗口内路面像素均值）：灰度差 >30 或饱和度 >0.35 的路面内非沥青像素为车辆候选；
   宽度 <5 px 的细长亮白 / 黄色线状目标判为车道线并剔除；闭运算合并车身与车窗，开运算去噪。
3. 连通域按长宽比（1.15~4.5）、矩形度（≥0.5）筛选，粘连的排队车辆按单车面积中位数折算数量。
4. 占有率 → 等效 TPI：车道全部排队（阻塞密度约 140 veh/km/车道）时占有率约 0.33 → TPI 10；
   临界密度约为阻塞密度的 1/3（占有率约 0.11）→ TPI 4。锚点 `[0, .06, .11, .17, .24, .33] → [0, 2, 4, 6, 8, 10]`。

**局限**：只适用于近似正射、道路走向与画面大致对齐的航拍；深色车辆与阴影、浅色车辆与路面标线的区分依赖阈值。

## 3. 建筑

### 3.1 SettleWatch · 沉降监测（`building.py`）

- 近 30 天 **Theil–Sen** 稳健斜率（所有点对斜率的中位数，崩溃点 29.3%）→ 沉降速率（mm/月，1 月按 30.44 天）；
- 近 90 天二次多项式拟合的二阶导 → 加速度（mm/月²）；
- 15 点滚动中位数 + MAD 修正 z 分数（Iglewicz & Hoaglin，|z|>3.5）→ 异常测点；
- 风险分级（阈值可配置，`SettlementThresholds`）：
  - `normal`：|速率| ≤ 2 mm/月；
  - `watch`：|速率| > 2 mm/月，或近 30 天异常测点 ≥ 3 个；
  - `warning`：|速率| > 4 mm/月，或 |速率| > 2 mm/月 且同向加速度 > 0.5 mm/月²（加速沉降）。

阈值依据：JGJ 8-2016《建筑变形测量规范》以最后 100 d 沉降速率小于 0.01~0.04 mm/d（约 0.3~1.2 mm/月）作为沉降稳定判据；
本系统的关注 / 预警阈值取该量级的数倍，是**演示用的工程经验值**，实际项目须按结构类型、地基条件与设计允许值重新标定。
示例中单点 −3.2 mm 的测量粗差被识别为异常测点，而 Theil–Sen 速率不受其影响。

### 3.2 ChangeScope · 前后时相变化检测

1. 灰度化 + 轻度模糊，"后时相"按均值 / 标准差匹配到"前时相"（辐射归一化，消除成像亮度差异）；
2. 变化强度 = 0.55·灰度差 + 0.45·Sobel 梯度幅值差（结构变化），9×9 局部均值聚合；
3. 阈值 = max(Otsu, 8, 中位数 + 8σ_MAD)。噪声自适应下限保证"无变化"时不会被 Otsu 强行二分；
   Otsu 在两峰之间出现空直方格（类间方差平台）时取平台中点；
4. 形态学 + 连通域（≥0.2% 画面），按纹理 / 亮度变化给出类型初判（结构破损、拆除覆盖、新增构筑物等）。

**局限**：要求两期影像已配准；不同太阳高度角造成的阴影变化会被识别为变化；类型初判是启发式规则。

## 4. 内涝

### 4.1 AquaLevel · 积水监测时序（`flood.py`）

- 分级阈值（演示默认值，可配置）：**15 cm** 影响通行、**27 cm** 危及车辆（约小汽车排气管 / 半轮高度）、**40 cm** 严重积水；
- 涨水速率：滑动 10 分钟水位差（cm/10min）；趋势：末段 15 分钟 Theil–Sen 斜率；
- 雨洪响应：降雨序列与水位增量的互相关，取相关系数最大的滞后（0~180 分钟）；示例 `flood-01` 估计滞后 25 分钟（r=0.90），与生成模型一致；
- 预测：**ARX(1)** 降雨-径流模型 `L_t = a·L_{t−1} + b·R_{t−lag} + c`（最小二乘），利用"已降雨但尚未汇流"的滞后降雨外推未来水位，
  滞后窗口之外假设无新增降雨；无降雨列或模型不稳定（a∉(0,1) 或 b<0）时退化为阻尼 Holt。预测峰值越过阈值同样判为检出（提前预警）。

### 4.2 AquaSeg · 积水影像分割

水面似然 = 低纹理（11×11 局部标准差）×（浑浊泥水的黄褐色调似然，或与泥水相邻的低饱和亮灰蓝反光）→ 5×5 平滑 →
阈值 max(Otsu, 0.40) → 形态学 → 连通域，积水范围占画面 ≥4% 判为检出，并按范围分级（4% / 12% / 25%）。
**单张影像只能估计积水范围，不能估计水深**；对裸土、米黄色地面等相近色调会有误报风险。

## 6. 后端如何使用算法

- **AI 分析任务**（`POST /api/tasks`、`/api/tasks/upload`）：在线程池中运行，进度 10 → 35 → 70 → 100 经 WebSocket 推送；
  检出且提供了位置时生成 `source=ai_task` 的事件，证据图为算法标注图。
- **实时模拟器**：路况由车速模型驱动，TPI / 等级由 `speed_to_tpi` 计算；某路段持续严重拥堵时用 TrafficPulse 分析其最近 10 分钟实时序列，
  检出持续拥堵才生成事件；巡检流水线每隔 `CITYEYE_SIM_INTERVAL` 秒在示例数据（含反例）上运行算法，只有检出才生成事件。
- **事件等级**由算法指标映射（`services/events.py::severity_for`），例如火焰占比 ≥2% 为Ⅰ级、TPI≥9 的严重拥堵为Ⅱ级、
  沉降预警为Ⅱ级、预测积水 ≥50 cm 为Ⅰ级。
- **种子数据**中的历史事件同样由算法在示例影像或模拟历史序列上实际计算得到（见 `database/README.md`）。
